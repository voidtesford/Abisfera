# Abisfera — редактор анимаций (ProcAnim)

Отдельное приложение для Windows (работает и на Linux) для правки процедурных анимаций игры — прототипов
`procAnimScene`. Сейчас основной режим — **добивания** (две куклы: атакующий и жертва). Переключатель «Режим → Все
анимации» показывает все сцены по категориям (Добивания / Способности / Примеры / Прочее), так что любую анимацию
можно открыть и править.

Позы считает **тот же код, что и в игре**: `ProcAnimTimeline`, `ProcAnimScenePrototype`, `ProcAnimValidation` и
клиентский `ProcAnimPuppet` подключены в редактор как есть, без копий. Сверка с игрой: для всех 8 сцен позы совпадают
до бита (интеграционный тест `ProcAnimEditorTest.DumpFingerprints` против `--fingerprint` редактора, расхождение 0).

## Запуск

**Windows.** Распакуйте `AbisferaAnimEditor-win-x64.zip` куда угодно и запустите `AbisferaAnimEditor.exe`.
Это один файл, установка и .NET не нужны.

**Первый запуск.** Редактор попросит папку с репозиторием игры: корень репо или сразу `Resources`. Папку можно выбрать
кнопкой или вставить путь в поле. Папка запоминается в `%APPDATA%\AbisferaAnimEditor\settings.json`. Там же хранятся
выбранные расы, переключатели и размер окна. Если exe лежит внутри репозитория, папка находится сама. Сменить её:
«Файл → Сменить папку игры…». Можно и из командной строки: `AbisferaAnimEditor.exe --repo D:\abisfera`
(и `--scene <id>`, чтобы сразу открыть сцену).

**Linux (для проверки).** Соберите из исходников: `dotnet publish Tools/_CorvaxGoob/AnimEditor -c Release -r linux-x64`.
Нужен .NET SDK 10. Настройки лежат в `~/.config/AbisferaAnimEditor/`.

Ошибки пишутся в `crash.log` рядом с настройками.

## Окно

* **Слева** — список анимаций с поиском, по категориям. Внизу кнопка «+ Новое добивание…».
* **Панель сверху:**
  * режим;
  * **Кукла 1 / Кукла 2** — раса (все 32 расы игры, спрайты берутся из игры так же, как ProcAnim собирает куклу)
    и одежда (без одежды / комбинезон / броня Гилберта);
  * «Правим» — кукла 1, кукла 2 или обе;
  * инструменты «Вращать (R)» / «Двигать (G)»;
  * переключатели «Суставы», «Калька», «Кости», «Эффекты», «Процедурка».
* **В центре** — сцена в пиксельной графике, как в игре: кровь, вспышки, звёзды, лица, предметы. Суставы — белые
  точки, корень куклы — оранжевый прямоугольник под ногами, цель IK — голубой крестик.
* **Внизу** — транспорт (⏮ ◀| ▶ |▶ ⏭, «Повтор», скорость ×0.25…×2) и таймлайн:
  * линейка с битами (beat) и hit-stop;
  * строка «Кадры» — все ключи правимой куклы, между кадрами подписана их длительность;
  * по строке на каждую кость / реквизит / IK.
* **Справа — вкладки:**
  * **Кость** — X / Y / поворот ключа на курсоре, плавность ключа, список всех костей;
  * **Кадр** — номер кадра, длительность (со сдвигом всего, что после), плавность кадра, действия с кадром;
  * **Сцена** — название и категория для редактора, длина, проверка на ошибки, события;
  * **YAML** — вся сцена текстом, можно править и «Применить».

## Управление

**Мышь в сцене**

* ЛКМ по части тела — выбрать и тянуть:
  * «Вращать» поворачивает вокруг сустава. Работают мягкие ограничения суставов, как в игре: плечо, локоть, бедро,
    колено; отключаются переключателем «Суставы» (J);
  * «Двигать» смещает часть в пикселях.
* **Shift** во время перетаскивания — временно другой инструмент. **Ctrl** — шаг 15° или без округления пикселей.
* Оранжевый прямоугольник под ногами — двигать куклу по полу (ключи `move`, в тайлах).
* Голубой крестик — сдвинуть цель IK у конечности, которую ведёт IK.
* ПКМ / СКМ — двигать вид, колесо — масштаб (вокруг курсора), F — показать всё.
* Esc — отменить текущее перетаскивание.
* **Любая правка позы сразу записывает ключ в текущее время** (автоключ): кадр создаётся сам.

**Таймлайн**

* Клик — перемотка. Курсор прилипает к кадрам, с Ctrl — без прилипания.
* Тянуть ромб кадра — перенос кадра во времени (у всех дорожек куклы); тянуть ключ в строке кости — перенос одного ключа.
* ПКМ — меню: записать позу, дублировать, копировать, плавность кадра или ключа, удалить.
* Ctrl + колесо — масштаб времени, Shift + колесо — прокрутка, колесо — прокрутка дорожек.
* Форма ключа показывает плавность: ромб — плавная, круг — линейная, квадрат — скачок.

**Клавиши**

| Клавиша | Действие |
|---|---|
| Пробел | играть / пауза (hit-stop проигрываются в реальном времени) |
| ← / → | предыдущий / следующий кадр |
| `,` / `.` | шаг 0.01 с |
| Home / End | в начало / в конец |
| K (Insert) | записать позу = новый кадр |
| Ctrl+D | дублировать кадр (всё после сдвигается) |
| Del / Shift+Del | удалить кадр / ключ выбранной кости |
| Ctrl+C / Ctrl+V | копировать / вставить позу |
| Ctrl+Z / Ctrl+Y | отмена / повтор (300 шагов) |
| Ctrl+S / Ctrl+Shift+S | сохранить / сохранить как копию |
| Ctrl+N | новое добивание |
| Ctrl+E | экспорт кадра в PNG |
| Ctrl+0 | сбросить выбранную кость в 0 |
| R / G | вращать / двигать |
| 1 / 2 / 3 / Tab | правим куклу 1 / 2 / обе / следующую |
| O / B / J / L | калька / кости / ограничения суставов / повтор |
| F1 | подсказка по управлению |
| F5 | перечитать анимации с диска |

## Плавность (ease)

У каждого ключа есть плавность перехода в него:

* Плавно (InOut) — по умолчанию;
* Линейно;
* Разгон (In) / Торможение (Out);
* Скачок (Step);
* Замах (BackIn) / Перелёт (BackOut) / Замах и перелёт (BackInOut);
* Пружина (ElasticIn / ElasticOut);
* Удар со стопом (HitStop).

Плавность меняется во вкладке «Кость», для всего кадра — во вкладке «Кадр», или через ПКМ на таймлайне.

## Куда сохраняется

* **Существующая сцена** сохраняется в **свой же файл**, например `Resources/Prototypes/_CorvaxGoob/Gilbert/finisher.yml`:
  * меняются только изменённые строки, все комментарии и порядок полей остаются;
  * переводы строк (CRLF / LF) и BOM сохраняются;
  * файл пишется атомарно, через временный файл;
  * после записи редактор перечитывает результат и сверяет со сценой; при любом расхождении файл не трогается.
* **Новое добивание** и **копия** сохраняются в `Resources/Prototypes/_CorvaxGoob/ProcAnim/Editor/<id>.yml`.
* Перед сохранением сцена проверяется тем же `ProcAnimValidation`, что и в игре. Если есть проблемы, редактор
  спросит, сохранять ли всё равно.
* Поля, которые редактор не показывает (урон, звуки, предметы, stowHands, события…), не теряются: моделью служит само
  дерево YAML.

## Как игра подхватывает изменения

1. **При запуске сервера и клиента** все `procAnimScene` загружаются как обычные прототипы, ничего регистрировать не надо.
2. **Без перезапуска, на работающем сервере:** в игре откройте «Админ-меню → Adminbus → Загрузить прототип»
   (команда `loadprototype`) и выберите сохранённый `.yml`. Сцена обновится на сервере и у клиентов.
   Сервер берёт сцену по id при каждом запуске, поэтому новая версия играет сразу.
   В TOOLS-сборке клиента прототипы перезагружаются сами, когда окно игры получает фокус.
3. **Посмотреть в игре:**
   * `procanim preview <id сцены> [раса1] [раса2]` — рядом с админом появляются манекены нужных рас, им выдаются
     обязательные предметы сцены, сцена проигрывается. Через 3 с после конца манекены и выданные предметы удаляются.
     Пример: `procanim preview GilbertFinisherPhase1 Human Vulpkanin`.
   * `procanim play <id> <uid1> <uid2>` — проиграть на конкретных сущностях.
   * `procanim list` — список сцен по категориям.
4. **Чтобы Гилберт использовал новое добивание**, добавьте его id в `finisherWeights` компонента `GilbertAI`
   (`Resources/Prototypes/_CorvaxGoob/Gilbert/gilbert.yml`), например `finisherWeights: {GilbertFinisherPhase1: 1, MyFinisher: 1}`.
   Роли должны идти в том же порядке: `attacker`, потом `victim`.

## Изменения в игре (коммит)

* `ProcAnimScenePrototype`:
  * новое поле `category` (enum `ProcAnimCategory`: Other / Finisher / Ability / Example) — группа в списке редактора;
  * новое поле `editorName` — название в редакторе; игроку нигде не показывается.
  * 8 сцен игры размечены.
* `procanim preview` и `procanim list` (`ProcAnimPreviewSystem`, флаг Fun), строки локализации ru / en.
* Исходники редактора: `Tools/_CorvaxGoob/AnimEditor` (в решение игры не входят, на сборку игры не влияют).
  Движок (RobustToolbox) не менялся.

## Ограничения

* У кукол цвет кожи — по умолчанию для расы, причёска и глаза — фиксированные, из маркировок только обязательные.
  Одежда — три набора.
* В редакторе не правятся:
  * события (урон, звуки, кровь, hit-stop);
  * реквизит (создание / удаление props);
  * IK-веса и `views` / `hide`.
  Всё это правится во вкладке YAML. Существующие ключи реквизита и цели IK тянутся мышью.
* Процедурные слои (дыхание, ходьба, IK, взгляд, отдача) видны, но ключами не являются. Переключатель «Процедурка»
  показывает чистые ключи.
* Ограничения суставов при перетаскивании — мягкие: значение зажимается в пределы, которые игра применяет при
  проигрывании.
* Новые добивания сами в игре не появятся — их нужно подключить (`finisherWeights` или код способности).
* Отмена действий — в пределах открытой сцены, при переключении сцены история сбрасывается.

## Сборка (для разработчиков)

```
dotnet publish Tools/_CorvaxGoob/AnimEditor -c Release -r win-x64     # один AbisferaAnimEditor.exe
dotnet publish Tools/_CorvaxGoob/AnimEditor -c Release -r linux-x64
```

* Проект изолирован от сборки игры собственными `Directory.Build.props/targets/Packages.props`.
* Проверки без UI:
  * `--selftest <repo>` — все сцены: разбор, эмиссия, сохранение без изменений побайтно, правка с сохранением
    комментариев, undo, операции с кадрами;
  * `--render <repo> <scene> <t> out.png`;
  * `--fingerprint <repo> out.json` — для сверки с игрой через `ProcAnimEditorTest.DumpFingerprints`
    с `PROCANIM_FINGERPRINT_OUT`.
* Код:
  * `Model/` — YAML-модель, сохранение с diff, операции с ключами;
  * `Rendering/` — RSI, куклы, отрисовка;
  * `UI/` — Avalonia;
  * `Shims/` — заглушки типов движка для подключённых файлов игры.
